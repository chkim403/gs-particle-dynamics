# Real-World Multi-Object Interaction Dataset

This document contains information about the raw dataset files released for [*Learning a Particle Dynamics Model with Real-world Videos*](https://arxiv.org/abs/2605.23845) (CVPR 2026 Findings). 

## Root Structure

```text
.
├── bowling/
│   ├── scene_00001/
│   ├── scene_00002/
│   └── ...
├── cube_stacks/
│   ├── scene_00003/
│   ├── scene_00004/
│   └── ...
├── dataset_license.md
├── dataset_terms_of_use.md
└── raw_dataset.md
```

Scene counts:

- `bowling/`: 297 scenes
- `cube_stacks/`: 232 scenes
- Total: 529 scenes. For our experiments, we used 292 bowling scenes and 210 cube-stacks scenes; the remaining scenes were excluded because of issues observed in their preprocessed outputs, such as segmentation failures. The list of excluded scenes is available as `skip_list` in the released code (`tools/dataset.py`).

Scene IDs are not guaranteed to be continuous. Some scenes were manually removed after continuous recording when they were completely unusable.

## Scene Structure

Each scene contains four numeric camera-ID folders:

```text
<scenario>/scene_XXXXX/
├── 234322305266/
├── 248622303451/
├── 336222300744/
└── 336522303601/
```

The same four camera IDs are used across all released scenes.

## Camera Directory Structure

Each camera folder contains RGB images, stereo images, stereo depth (aligned with RGB pixels), segmentation masks, object poses, and per-camera metadata:

```text
<scenario>/scene_XXXXX/<camera_id>/
├── camera_meta.json
├── obj_poses.npz
├── rgb/
├── left/
├── right/
├── stereo_aligned_depth/
└── filtered_segmentation_DAM4SAM/
```

Note that segmentation, depth, obj_poses are generated by external algorithms described in the paper. As a result, they are not perfect ground truth. 


## Metadata

`camera_meta.json` is a per-camera JSON file with this structure:

```json
{
    "h": 480,
    "w": 640,
    "k": [[...], [...], [...]],
    "w2c": [[...], [...], [...], [...]],
    "depth_scale": 0.0010000000474974513
}
```

Fields:

- `h`, `w`: image height and width.
- `k`: 3x3 RGB camera intrinsic matrix.
- `w2c`: 4x4 world-to-camera extrinsic matrix.
- `depth_scale`: multiplier for converting stored depth values to metric depth (generated from Intel RealSense API).

`obj_poses.npz` stores pseudo object pose information for the corresponding camera.

## Image, Depth, and Segmentation Folders

`rgb/`, `left/`, and `right/` contain zero-padded `.jpg` image sequences:

```text
00000.jpg
00001.jpg
...
```

`stereo_aligned_depth/` contains zero-padded `.npy` depth arrays aligned to the RGB camera:

```text
00000.npy
00001.npy
...
```

`filtered_segmentation_DAM4SAM/` contains segmentation masks as zero-padded `.png` files. These masks cover the relevant interaction frames and may contain fewer frames than the full 120-frame RGB/depth streams.

## Notes

- RGB/stereo/depth streams contain full camera sequences, while segmentation masks cover selected interaction ranges chosen by human annotators.
- Object IDs in segmentation masks are intended to be consistent across time and views, but masks may contain noise from tracking and cross-view association.
